# Web UI internationalization (i18n)

The Polaris web UI uses an **"English source as key"** model (gettext-style):
the English text already in `index.html` / `app.js` *is* the lookup key. A
per-language catalog at `wwwroot/data/locales/{lang}.json` maps
`{ "English source": "Translation" }`. English is the identity language: no
catalog, no fetch, no runtime overhead.

Runtime: `wwwroot/js/i18n.js` (loaded before Alpine). For a non-English UI a
scoped `MutationObserver` translates text nodes + `title`/`placeholder`/
`aria-label`/`alt` by looking up their current English content, so static **and**
Alpine `x-text` output are translated without per-binding edits. JS-built strings
(toasts, chart labels) use `t()` / the Alpine `$t()` magic with `{var}`
interpolation. Untranslated strings fall back to English. Language change reloads
the page. Hot/numeric regions opt out via `data-no-i18n`.

Released languages: `en` (source) + `pt-BR`, `es`, `fr`, `de`.

## Workflow

1. **Extract** the source strings (run after UI text changes):
   ```
   node scripts/extract-i18n.mjs
   ```
   Writes `wwwroot/data/locales/_source.json` (decoded, high-precision filter;
   reports orphans). This is the Crowdin source and the input to MT.

2. **Bulk machine pre-translation** (fills only missing keys; never overwrites
   existing/curated ones; applies `scripts/i18n-glossary.json`). The provider
   key/URL comes from an environment variable.

   PowerShell (Windows):
   ```powershell
   $env:DEEPL_API_KEY = "xxxx"
   node scripts/pretranslate-i18n.mjs            # all released langs
   node scripts/pretranslate-i18n.mjs pt-BR      # one lang
   # LibreTranslate instead of DeepL:
   $env:LIBRETRANSLATE_URL = "http://localhost:5000"; node scripts/pretranslate-i18n.mjs
   ```
   bash/zsh (Linux/macOS):
   ```bash
   DEEPL_API_KEY=xxxx node scripts/pretranslate-i18n.mjs
   LIBRETRANSLATE_URL=http://localhost:5000 node scripts/pretranslate-i18n.mjs
   ```
   Machine-filled keys are recorded in `{lang}.machine.json` (needs review).
   With no provider configured the script exits without touching the catalog;
   it never invents translations. (DeepL Free has a monthly character quota;
   `403 Forbidden` usually means the quota is spent; it resets monthly.)

3. **Curated corrections** (fix MT homographs / pin jargon): edit
   `scripts/i18n-overrides.json` (`all` = every language; per-language sections
   override it), then:
   ```
   node scripts/apply-i18n-overrides.mjs
   ```
   This overwrites those keys and de-marks them as machine output. Re-run any
   time after a fresh pre-translation.

4. **Community refinement via Crowdin** (`crowdin.yml`): English is the source
   language; Crowdin's own MT pre-translation can seed empty strings, then the
   community reviews. `crowdin upload sources` / `crowdin pull`.

## Conventions

- Jargon / product names stay English (see `i18n-glossary.json`
  `doNotTranslate`): ASTAP, ONNX, OpenCL, INDI, ASCOM, PHD2, GraXpert, FITS,
  HFR, plate solving, dithering, etc.
- Endonyms in the language picker are never translated (`data-no-i18n`).
- Server logs and backend error strings stay `en-US` by design (Program.cs).
- Don't hand-edit `Locale.*` from desktop NINA; Polaris is a separate catalog.

## Adding a language

Add the code to `SUPPORTED` in `wwwroot/js/i18n.js`, to the picker in
`index.html` (Settings → Appearance), to `RELEASED` in `pretranslate-i18n.mjs`,
and a `languages_mapping` entry in `crowdin.yml`; then run the pre-translation.
