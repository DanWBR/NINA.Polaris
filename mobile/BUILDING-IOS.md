# Building the Polaris iOS app

The mobile app is a **Capacitor** project (the same `www/` shell + native
plugins as Android). The iOS side is already scaffolded — the
`polaris-onnx` plugin ships a full Swift/Obj-C implementation
(`plugins/polaris-onnx/ios/Plugin/`) that runs ONNX Runtime with the
**CoreML** execution provider, and `capacitor.config.ts` has an `ios`
block. What's missing is the generated `ios/` Xcode project and a signed
build.

> **You need a Mac.** iOS builds require **macOS + Xcode** — there is no
> Windows/Linux path. `npx cap add ios` runs `pod install` (CocoaPods,
> macOS only), and the `.ipa` only comes out of Xcode. Do **not** run
> `cap add ios` on Windows; it produces a broken half-project. Everything
> below happens on a Mac.
>
> No Mac? Options: a cloud Mac (MacStadium / MacinCloud), a **GitHub
> Actions `macos-latest`** runner to build in CI, or Ionic Appflow. The
> steps are the same; only the machine changes.

Everything here happens inside `mobile/`. Nothing touches the rest of the
repo (`mobile/` is outside `NINA.sln`).

---

## 1. Install the toolchain (once, on the Mac)

- **Xcode** (Mac App Store). Open it once to finish component install and
  accept the license (`sudo xcodebuild -license accept`).
- **Command Line Tools**: `xcode-select --install`.
- **CocoaPods**: `sudo gem install cocoapods` (or `brew install cocoapods`).
- **Node 18+** (`brew install node` or nvm).
- An **Apple ID**. A free Apple ID signs and runs on *your own* device
  (7-day provisioning, re-sign weekly). **TestFlight / ad-hoc / App Store**
  distribution needs the paid **Apple Developer Program** (US$99/yr).

---

## 2. One-time project setup (on the Mac)

```bash
cd mobile
npm install                # app deps (Capacitor, plugins)
npm run plugin:build       # compiles the local polaris-onnx plugin  <-- REQUIRED first
npx cap add ios            # generates the mobile/ios Xcode project + runs pod install
npx cap sync ios           # copies www/ + plugins, refreshes Pods
```

`npm run plugin:build` must run **before** `cap sync`, otherwise the native
ONNX plugin won't be bundled. Re-run `npx cap sync ios` any time you change
files under `www/` or the plugin.

### App icon

The launcher icon is generated from the source images in `mobile/assets/`
(same set as Android). `@capacitor/assets` writes **both** platforms:

```bash
npm run icons              # writes AppIcon.appiconset into ios/ (and Android)
npx cap sync ios
```

Re-run after any fresh `cap add ios` (the `ios/` folder is git-ignored and
regenerated).

### Required Info.plist entries (after `cap add ios`)

`ios/` is git-ignored (regenerated by `cap add`), so these must be
re-applied after a fresh `cap add ios`. **The easy way** — run the helper
(idempotent), then sync:

```bash
./scripts/ios-postadd.sh
npx cap sync ios
```

It writes all of the keys below via `PlistBuddy`. If you'd rather do it by
hand, edit `ios/App/App/Info.plist`:

- **Location usage string** — `@capacitor/geolocation` is a dependency; iOS
  crashes on the permission prompt without a description. Add:
  ```xml
  <key>NSLocationWhenInUseUsageDescription</key>
  <string>Polaris uses your location for polar-alignment and target planning.</string>
  ```
- **App Transport Security** — the app navigates to a LAN host over HTTPS
  with a **self-signed** cert (e.g. `https://polaris-app.local:5000`) and to
  arbitrary local hosts. `capacitor.config.ts` already sets
  `ios.limitsNavigationsToAppBoundDomains: false`; also relax ATS so local
  loads aren't blocked:
  ```xml
  <key>NSAppTransportSecurity</key>
  <dict>
    <key>NSAllowsLocalNetworking</key><true/>
  </dict>
  ```
- **Local Network usage** (iOS 14+ needs this for mDNS/`.local` discovery
  and LAN sockets used by `capacitor-zeroconf`):
  ```xml
  <key>NSLocalNetworkUsageDescription</key>
  <string>Polaris finds your telescope controller on the local network.</string>
  <key>NSBonjourServices</key>
  <array><string>_polaris._tcp</string><string>_http._tcp</string></array>
  ```

## 3. The self-signed LAN cert (important — iOS is stricter than Android)

On Android we blanket-allow the Pi's self-signed HTTPS (`allowMixedContent`).
**iOS `WKWebView` does not offer that escape hatch** — it will refuse to
load `https://polaris-app.local:5000` if the cert isn't trusted, with no
in-app "accept" UI.

The supported path is to **trust the Pi's root cert on the device**:

1. In Polaris, open **Settings → Remote access / TLS → Install root
   certificate** (the built-in wizard) and download the root CA, or fetch it
   from `/api/system/server-cert`.
2. Install it on the iPhone/iPad (AirDrop / email / Files → tap the
   `.crt` → **Install Profile**).
3. **Settings → General → VPN & Device Management** → install the profile,
   then **Settings → General → About → Certificate Trust Settings** →
   toggle **full trust** on for that root.
4. Now `https://polaris-app.local:5000` loads cleanly in the app.

(Over the Relay you get a real public cert, so this only affects direct-LAN
HTTPS.)

---

## 4. Build & run

```bash
npx cap open ios           # opens mobile/ios/App.xcworkspace in Xcode
```

In Xcode:
1. Select the **App** target → **Signing & Capabilities** → set your
   **Team** (your Apple ID). Xcode auto-manages the provisioning profile.
2. Pick a **Simulator** or a connected **device** (a real device is needed
   to test camera/LAN/CoreML; the simulator can't reach a real Pi cert
   easily and has no Neural Engine).
3. Press **Run ▶**.

CLI equivalent: `npx cap run ios` (builds and launches on a selected
target).

> **Simulator note:** ONNX with the CoreML EP falls back to CPU in the
> Simulator (no ANE). For real inference timing, test on a device.

---

## 5. Distribution

- **Personal device, free Apple ID:** just Run from Xcode. The app expires
  after ~7 days; re-run to re-sign.
- **TestFlight / ad-hoc (needs paid Developer Program):** Xcode → **Product
  → Archive** → **Distribute App** → **App Store Connect** (TestFlight) or
  **Ad Hoc** (up to 100 registered UDIDs). Bump `version`/build first.
- There is **no** unsigned "sideload an .ipa to anyone" path like Android's
  APK; Apple requires provisioning per device or TestFlight.

## 6. Common snags

- **`pod install` fails / "unable to find a specification for
  onnxruntime-objc"**: `pod repo update`, then `npx cap sync ios`. Make sure
  CocoaPods is current (`sudo gem install cocoapods`).
- **"Signing requires a development team"**: set the Team under Signing &
  Capabilities; a free Apple ID works for on-device debug.
- **White screen / can't reach the host**: almost always the **cert trust**
  step (§3) or a missing **ATS / Local Network** key (§2). Check the Xcode
  console for an ATS or TLS rejection.
- **mDNS host doesn't appear**: iOS needs the **Local Network** permission
  (prompted on first use) plus `NSBonjourServices` (§2). Type the host
  manually (`polaris-app.local:5000`) to confirm the rest works.
- **Plugin changes not showing**: re-run `npm run plugin:build` then
  `npx cap sync ios`; in Xcode, **Product → Clean Build Folder**.
- **WASM/WebGL in the Polaris UI**: WKWebView on iOS 14+ runs the WebGL +
  WASM SPA fine. Heavy in-browser ONNX (ORT Web) may be slower than on
  desktop; the **native** `polaris-onnx` plugin (CoreML) is the fast path
  and is what the shell injects.

---

## 7. First smoke test

1. Install/run on a device on the same Wi-Fi as the Pi.
2. Trust the Pi root cert (§3) if using direct-LAN HTTPS.
3. The **connect** screen should auto-list the host (mDNS), or type
   `polaris-app.local:5000`. Tap to load the live UI in the tab.
4. **Tools → Aim helper → Polar align** works offline with just your
   latitude — a good first validation with no telescope.
